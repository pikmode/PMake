--------------------------------------------------------------------------------
1. Введение
--------------------------------------------------------------------------------

PMake — декларативная система сборки с императивными возможностями.
Язык build.pmake сочетает простоту Ninja с гибкостью скриптового языка.

Ключевые принципы:
  - Явность — одна конструкция делает одно дело.
  - Кроссплатформенность — Windows, Linux, macOS.
  - Скорость — инкрементальная сборка, параллелизм, бинарный кэш, LTO.

--------------------------------------------------------------------------------
2. Лексика и синтаксис
--------------------------------------------------------------------------------

2.1 Комментарии
  // однострочный (до конца строки)
  /* многострочный */

2.2 Идентификаторы
  - Буквы A-Z a-z, цифры 0-9, подчёркивание _, точка .
  - Ограничение: точка не может быть первой.
  - Примеры: my_var, compiler.path, _internal

2.3 Строки
  - Заключаются в двойные кавычки: "text"
  - Экранирование: \", \\, \n, \r, \t
  - Обязательны для имён файлов, путей и значений с пробелами.

2.4 Числа и булевы
  - Целые и дробные: 42, -10, 3.14
  - Булевы: true, false (в условиях работают как логические)

--------------------------------------------------------------------------------
3. Переменные и Области видимости
--------------------------------------------------------------------------------

3.1 Объявление и присваивание
  name = "value"

3.2 Подстановка
  ${name} — везде, где ожидается строка (в командах, атрибутах, условиях).

3.3 Конкатенация через +=
  cflags = "-Wall"
  cflags += "-O2"   // cflags = "-Wall -O2" (добавляет пробел)

3.4 Области видимости
  - Глобальная — объявления вне блоков.
  - Локальная — внутри build, if, foreach, function.
  - Локальные переменные не влияют на глобальные, если не используются функции изменения.

--------------------------------------------------------------------------------
4. Типы данных
--------------------------------------------------------------------------------

  Строка  "текст"         [OK]
  Число   123 или 3.14    [OK]
  Булев   true/false      [OK]
  Список  [ "a", "b" ]    [NO] (используйте строки с пробелами)
  Null    null            [NO]

--------------------------------------------------------------------------------
5. Блоки
--------------------------------------------------------------------------------

Блоки обозначаются { ... } и используются для группировки инструкций.
Виды блоков:
  - rule name { ... }
  - build "out" : rule "in" { ... }
  - if (cond) { ... } else { ... }
  - foreach var in list { ... }
  - function name(args) { ... }
  - namespace name { ... }

--------------------------------------------------------------------------------
6. Правила (Rules)
--------------------------------------------------------------------------------

Правило — шаблон команды.

rule compile {
    command = "${compiler} ${cflags} -c ${in} -o ${out}"
    description = "Compiling ${in}"
    depfile = "${out}.d"
    deps = "gcc"
    generator = false
    restat = false
    rspfile = "${out}.rsp"
    rspfile_content = "${in}"
    pool = "console"
}

Специальные переменные:
  ${in}          — все входы (экранируются)
  ${out}         — все выходы (экранируются)
  ${in_newline}  — входы через перевод строки

--------------------------------------------------------------------------------
7. Сборки (Build)
--------------------------------------------------------------------------------

Создание цели из входов по правилу.

build "main.o" : compile "main.cpp" {
    cflags = "-g -O0" // локальные переменные переопределяют глобальные
}

Синтаксис:
  build "out1" "out2" : rule "in1" "in2" || "order-only" | "implicit" { ... }

--------------------------------------------------------------------------------
8. Управляющие конструкции (if / foreach / while / switch)
--------------------------------------------------------------------------------

if os == "windows" {
    defines = "-DWIN32"
} elseif os == "linux" {
    defines = "-DLINUX"
} else {
    defines = "-DUNKNOWN"
}

foreach src in ${sources} {
    // Переменная src доступна внутри блока
    // Поддерживаются continue и break
    if src == "ignore.cpp" { continue }
    if src == "stop.cpp" { break }
}

while count < 10 {
    count += 1
    if count == 5 { break }
}

switch version {
case "1.0" { current = "stable" }
case "2.0" { current = "next" }
default { current = "unknown" }
}

Операторы: ==, !=, <, >, <=, >=, &&, ||, !

11. Алиасы (Alias)
--------------------------------------------------------------------------------

alias all : "app.exe", "lib.a"

Создаёт цель с правилом phony, зависящую от перечисленных целей.
ВАЖНО: цели перечисляются через запятую.

--------------------------------------------------------------------------------
12. Практические советы по написанию build.pmake
--------------------------------------------------------------------------------

1. Всегда ставьте кавычки вокруг имён файлов и целей.
2. Используйте += для накопления флагов и путей.
3. Выносите общие правила и функции в отдельные файлы (include/import).
4. Проверяйте синтаксис перед коммитом.
5. Используйте флаг -v (verbose) для отладки (показывает description, command, workdir).
6. Для инкрементальной сборки используйте depfile, restat и бинарный кэш.
7. Если кэш повреждён, удалите Project-cache.pmake.
8. Используйте 'pmake clean' для удаления артефактов сборки.

--------------------------------------------------------------------------------
13. Пример полноценного build.pmake
--------------------------------------------------------------------------------

pmake_required_version = 1.0

project = "MyApp"

if os == "windows" {
    cxx = "g++"
    cflags = "-O2 -DNDEBUG"
    exe_suffix = ".exe"
} else {
    cxx = "g++"
    cflags = "-O2"
    exe_suffix = ""
}

rule compile {
    command = "${cxx} -c ${cflags} -MMD -MP -MF ${out}.d ${in} -o ${out}"
    description = "Compiling ${in}"
    depfile = "${out}.d"
    deps = "gcc"
    restat = true
}

rule link {
    command = "${cxx} ${in} -o ${out}"
    description = "Linking ${out}"
}

sources = glob("*.cpp", "src")
objects = ""

foreach src in ${sources} {
    // Генерация уникальных имён для объектов (защита от коллизий)
    rel = relative_path("${src}", "src")
    name = replace("${rel}", "/", "_")
    obj = "build/${name}.o"
    build "${obj}" : compile "${src}"
    objects += "${obj}"
}

target = "build/myapp${exe_suffix}"
build "${target}" : link ${objects}
alias all : "${target}"

15. Особенности работы кэша
--------------------------------------------------------------------------------

PMake использует бинарный кэш (Project-cache.pmake), который содержит:
- Версию и mtime главного файла и всех включённых.
- Глобальные и локальные переменные, правила, сборки.
- Состояния файлов (mtime, size) для листовых узлов.
- Неявные зависимости (depsLog) из .d файлов.

При отсутствии кэша PMake пересобирает все цели (полный rebuild).
Кэш сохраняется после успешной сборки.

--------------------------------------------------------------------------------
16. Особенности Windows
--------------------------------------------------------------------------------

Для выполнения встроенных команд (mkdir, rmdir, copy и т.д.) используйте:
    command = "cmd /c \"mkdir ${dirname(out)} 2>nul & ...\""

PMake автоматически добавляет расширение .exe при поиске в PATH на Windows.
