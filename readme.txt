================================================================================
PMake: Документация (актуальная версия)
================================================================================

Версия синтаксиса: 1.0 (расширяемая)
Состояние: отражает реальную реализацию после критических исправлений.

--------------------------------------------------------------------------------
1. Введение
--------------------------------------------------------------------------------

PMake — декларативная система сборки с императивными возможностями.
Язык build.pmake сочетает простоту Ninja с гибкостью скриптового языка.

Ключевые принципы:
  - Явность — одна конструкция делает одно дело.
  - Расширяемость — новые фичи не ломают старые файлы.
  - Скорость — инкрементальная сборка, параллелизм, бинарный кэш.

--------------------------------------------------------------------------------
2. Лексика и синтаксис
--------------------------------------------------------------------------------

2.1 Комментарии
  // однострочный (до конца строки)
  /* многострочный (но лучше использовать //) */

2.2 Идентификаторы
  - Буквы A-Z a-z, цифры 0-9, подчёркивание _, точка .
  - Ограничение: точка не может быть первой.
  - Примеры: my_var, compiler.path, _internal

2.3 Строки
  - Заключаются в двойные кавычки: "text"
  - Экранирование: \", \\, \n, \r, \t
  - Обязательны для имён файлов, путей и значений с пробелами.

2.4 Числа и булевы
  - Целые и дробные: 42, -10, 3.14
  - Булевы: true, false (в условиях работают как логические)

--------------------------------------------------------------------------------
3. Переменные
--------------------------------------------------------------------------------

3.1 Объявление и присваивание
  name = "value"

3.2 Подстановка
  ${name} — везде, где ожидается строка
  Работает в командах, атрибутах, условиях, путях.

3.3 Конкатенация через +=
  cflags = "-Wall"
  cflags += "-O2"   # теперь cflags = "-Wall -O2"
  Добавляет пробел между старым и новым значением.

3.4 Области видимости
  - Глобальная — объявления вне блоков.
  - Локальная — внутри build, if, foreach, function.
  - Локальные переменные не влияют на глобальные.

--------------------------------------------------------------------------------
4. Типы данных
--------------------------------------------------------------------------------

  Строка  "текст"         [OK]
  Число   123 или 3.14    [OK]
  Булев   true/false      [OK]
  Список  [ "a", "b" ]    [NO] (не реализован, используйте строки с пробелами)
  Null    null            [NO]

--------------------------------------------------------------------------------
5. Блоки
--------------------------------------------------------------------------------

Блоки обозначаются { ... } и используются для группировки инструкций.
Виды блоков:
  - rule name { ... }
  - build "out" : rule "in" { ... }
  - if (cond) { ... } else { ... }
  - foreach var in list { ... }
  - function name(args) { ... }
  - alias name : target   (блоки пока не поддерживаются)

--------------------------------------------------------------------------------
6. Правила (Rules)
--------------------------------------------------------------------------------

Правило — шаблон команды.

rule compile {
    command = "${compiler} ${cflags} -c ${in} -o ${out}"
    description = "Compiling ${in}"
    depfile = "${out}.d"      // [OK]
    deps = "gcc"              // [OK]
    generator = false         // [OK]
    restat = false            // [OK]
    rspfile = "${out}.rsp"    // [OK] (реализовано)
    rspfile_content = "${in}" // [OK] (реализовано)
    pool = "console"          // [OK] (ограничение 1 задача)
}

Специальные переменные в команде:
  ${in}          — все входы, разделённые пробелами (автоматически экранируются)
  ${out}         — все выходы, разделённые пробелами (автоматически экранируются)
  ${in_newline}  — входы, разделённые переводами строк
  Локальные переменные из build переопределяют глобальные.

--------------------------------------------------------------------------------
7. Сборки (Build)
--------------------------------------------------------------------------------

Сборка создаёт цель из входов по правилу.

build "main.o" : compile "main.cpp" {
    cflags = "-g -O0"
}

Синтаксис:
  build "выход1" "выход2" ... : правило "вход1" "вход2" ... {
      локальные переменные
  }

Правила:
  - Имена выходов и входов обязательно в кавычках.
  - Локальные переменные переопределяют глобальные для этой сборки.
  - += в локальном блоке работает (добавляет к глобальному значению).
  - Несколько выходов поддерживаются.

--------------------------------------------------------------------------------
8. Условные операторы (if / elseif / else)
--------------------------------------------------------------------------------

if os == "windows" {
    defines = "-DWIN32"
} elseif os == "linux" {
    defines = "-DLINUX"
} else {
    defines = "-DUNKNOWN"
}

Операторы:
  - Сравнение: ==, !=, <, >, <=, >=
  - Логические: &&, ||, !
  - Группировка: ( ... )

Условия вычисляются на этапе парсинга.

--------------------------------------------------------------------------------
9. Циклы (foreach)
--------------------------------------------------------------------------------

foreach перебирает элементы, разделённые пробелами в строке.
Для генерации уникальных имён выходных файлов используйте relative_path
и replace, а не basename! (подробнее в разделе «Практические советы»)

sources = "src/main.cpp src/foo.cpp src/bar.cpp"

foreach src in ${sources} {
    // [BAD] basename может дать коллизию при одинаковых именах в разных папках:
    // obj = "build/${basename(src)}.o"

    // [GOOD] уникальное имя на основе относительного пути:
    rel = relative_path("${src}", "src")
    base = replace("${rel}", "/", "_")
    obj = "build/${base}.o"
    build "${obj}" : compile "${src}"
}

Особенности:
  - Список — строка с пробелами (до реализации списков [ ... ]).
  - Переменная цикла доступна внутри блока.
  - Тело может содержать любые конструкции.

10. Функции
--------------------------------------------------------------------------------

10.1 Встроенные функции (все работают)

  basename(path)               -> имя файла без расширения
  dirname(path)                -> путь к папке
  extension(path)              -> расширение файла
  filename(path)               -> полное имя файла
  glob(pattern, dir)           -> поиск файлов (возвращает список)
  replace_suffix(list, suffix) -> замена расширений
  join(list, glue)             -> склейка списка
  relative_path(path, base)    -> относительный путь
  exists(path)                 -> true/false
  file_mtime(path)             -> число (mtime)
  read_file(path)              -> содержимое
  write_file(path, content)    -> true/false
  env(name)                    -> переменная окружения
  cwd()                        -> текущая директория
  absolute_path(path)          -> абсолютный путь
  hash(str)                    -> SHA1 хеш (hex)
  split(str, delim)            -> список строк
  replace(str, from, to)       -> замена подстроки
  starts_with(str, prefix)     -> true/false
  ends_with(str, suffix)       -> true/false
  contains(str, substr)        -> true/false

10.2 Пользовательские функции

function add_flags(flags) {
    cflags = "${cflags} ${flags}"
}

add_flags("-Wall -Wextra")

Особенности:
  - Параметры передаются по значению.
  - Тело выполняется в текущей области видимости (может изменять глобальные переменные).
  - Вложенные вызовы поддерживаются (глубина до 100).
  - Возврат значений пока не реализован (планируется).

11. Алиасы (Alias)
--------------------------------------------------------------------------------

alias all : "app.exe" "lib.a"

Создаёт цель с правилом phony, зависящую от перечисленных целей.
Внимание: в текущей реализации алиас требует перечисления целей через запятую:
  alias all : "app.exe", "lib.a"

14. Практические советы по написанию build.pmake
--------------------------------------------------------------------------------

1. Всегда ставьте кавычки вокруг имён файлов и целей.
2. Используйте += для накопления флагов и путей.
3. Выносите общие правила и функции в отдельные файлы.
4. Пишите комментарии, чтобы объяснить неочевидные моменты.
5. Проверяйте синтаксис перед коммитом (запуском PMake).
6. Используйте --verbose для отладки.
7. Для инкрементальной сборки используйте depfile и restat.
8. Если кэш повреждён, удалите Project-cache.pmake и выполните сборку.

--------------------------------------------------------------------------------
15. Генерация уникальных имён в foreach (критически важно!)
--------------------------------------------------------------------------------

Проблема: если в проекте есть два файла с одинаковым именем, но в разных папках
(например, src/core/logger.cpp и src/utils/logger.cpp), то basename даст
одинаковое имя "logger", и сборка попытается создать два объекта с одинаковым именем,
что приведёт к конфликту.

Решение: используйте relative_path + replace, чтобы включить путь в имя.

Пример для заголовочных файлов (MOC):
headers = "src/core/logger.h src/utils/logger.h"

foreach hdr in ${headers} {
    rel = relative_path("${hdr}", "src")
    base = replace("${rel}", "/", "_")
    base = replace("${base}", "\\", "_")
    moc_cpp = "build/moc_${base}.cpp"
    build "${moc_cpp}" : moc "${hdr}"
    // ... остальные действия
}

Для исходников аналогично:
sources = "src/main.cpp src/core/logger.cpp src/utils/logger.cpp"

foreach src in ${sources} {
    rel = relative_path("${src}", "src")
    base = replace("${rel}", "/", "_")
    obj = "build/${base}.o"
    build "${obj}" : compile "${src}"
}

Так вы получите:
  build/main.o
  build/core_logger.o
  build/utils_logger.o
 — уникальные имена без конфликтов.

--------------------------------------------------------------------------------
16. Пример полноценного build.pmake (только реализованные фичи)
--------------------------------------------------------------------------------

pmake_required_version = 1.0

project = "MyApp"

// Определяем компилятор и флаги в зависимости от ОС
if os == "windows" {
    cxx = "g++"
    cflags = "-O2 -DNDEBUG"
    exe_suffix = ".exe"
} elseif os == "darwin" {
    cxx = "clang++"
    cflags = "-O2"
    exe_suffix = ""
} else {
    cxx = "g++"
    cflags = "-O2"
    exe_suffix = ""
}

// Правило компиляции с depfile
rule compile {
    command = "${cxx} -c ${cflags} -MMD -MP -MF ${out}.d ${in} -o ${out}"
    description = "Compiling ${out}"
    depfile = "${out}.d"
    deps = "gcc"
    restat = true
}

// Правило линковки
rule link {
    command = "${cxx} ${in} -o ${out}"
    description = "Linking ${out}"
}

// Автоматический поиск исходников в папке src
sources = glob("*.cpp", "src")

// Генерация объектных файлов с уникальными именами
objects = ""
foreach src in ${sources} {
    rel = relative_path("${src}", "src")
    name = replace("${rel}", "/", "_")
    obj = "build/${name}.o"
    build "${obj}" : compile "${src}"
    objects += "${obj}"
}

// Сборка исполняемого файла
target = "build/myapp${exe_suffix}"
build "${target}" : link ${objects}

// Алиас по умолчанию (через запятую)
alias all : "${target}"

// Алиас для очистки
alias clean : ${target} ${objects}

19. Особенности работы кэша
--------------------------------------------------------------------------------

PMake использует бинарный кэш (Project-cache.pmake), который содержит:
- Версию и mtime главного файла и всех включённых.
- Глобальные и локальные переменные, правила, сборки.
- Состояния файлов (mtime, size) для листовых узлов.
- Неявные зависимости (depsLog) — записи вида выходной_файл -> [входные_файлы].

На основе depsLog при необходимости строится обратный индекс (input -> outputs),
который позволяет при изменении заголовочного файла найти все объектные файлы,
которые его используют, и пересобрать только их.

Если кэш невалиден (изменился build.pmake или включённые файлы),
PMake очищает устаревший depsLog и перечитывает все .d файлы заново.

ВАЖНО: при отсутствии кэша (например, после удаления Project-cache.pmake)
PMake пересобирает все цели, так как не имеет информации о предыдущих состояниях
файлов. Это нормальное поведение, обеспечивающее корректность сборки.
Для инкрементальной сборки необходимо сохранять кэш между запусками.

--------------------------------------------------------------------------------
20. Особенности Windows
--------------------------------------------------------------------------------

На Windows для выполнения встроенных команд (mkdir, rmdir, copy и т.д.)
необходимо вызывать их через cmd.exe, так как они не являются отдельными
исполняемыми файлами. В правилах следует использовать:

    command = "cmd /c mkdir ${dirname(out)} 2>nul & ..."

либо задать переменную cmd = "C:/Windows/System32/cmd.exe" и использовать её.

Если PMake не находит программу в PATH (например, g++), убедитесь, что
переменная PATH содержит путь к исполняемым файлам, или укажите полный путь.

PMake автоматически добавляет расширение .exe при поиске в PATH на Windows,
что упрощает вызов команд без указания полного пути.
