# Ninja Compatibility

PMake can parse `build.ninja` files generated by CMake, GN, or Meson.
It reads them directly — no conversion, no glue scripts.

## Supported

| Feature | Status |
|---|---|
| `rule` | ✅ |
| `build` | ✅ |
| `default` | ✅ |
| `pool` | ✅ |
| `include` / `subninja` | ✅ |
| `$in`, `$out`, `${var}` | ✅ |
| Escapes: `$:`, `$ `, `$$` | ✅ |
| Multi-line `$<newline>` | ✅ |
| `\|` (implicit inputs) | ✅ |
| `\|\|` (order-only) | ✅ |
| `depfile` | ✅ |
| `deps = gcc` | ✅ |
| `rspfile` / `rspfile_content` | ✅ |
| `restat` | ✅ |
| `generator` | ✅ |
| `pool = console` | ✅ |
| Windows drive letters (`E$:/`) | ✅ |

## Not yet supported

| Feature | Impact |
|---|---|
| Implicit outputs (`\|` before `:`) | Rare in CMake output |
| `dyndep` | C++20 modules only |
| `phony` with no rule name | Rare |

## How to use

```bash
cmake -G Ninja -S . -B build -DCMAKE_BUILD_TYPE=Release
cd build
pmake
# Or explicitly select the manifest from this directory:
pmake -f build.ninja
```

PMake resolves relative paths from the current working directory. Running from
the build directory keeps paths in the generated Ninja file consistent.

## What's different from `ninja`

- **Cache**: PMake has its own binary cache (`Project-cache.pmake`),
  not `.ninja_deps` / `.ninja_log`. First run on a new project re-scans
  all `.d` files.
- **Manifest regen**: both auto-regenerate on `CMakeLists.txt` change.
  PMake also restarts itself after regen (like ninja).
- **`-t clean`**: PMake's clean tool doesn't run `ninja -t clean`. It removes
  outputs from the parsed state — same result, but skips rspfiles that
  were deleted by the build itself.
- CMake's `clean` and `help` targets invoke Ninja's `CLEAN` / `HELP` rules.
  PMake runs these command-only rules without requiring a file named after
  the target and forwards their output.
- **`compile_commands.json`**: PMake does not export it yet. CMake can generate
  it separately with `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON`.
